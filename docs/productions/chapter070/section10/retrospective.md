## 1. 分镜阶段：局部返修没有始终带着整套设定一起检查

| 出现的问题 | 本次应保留的判断 | 后续做法 |
| --- | --- | --- |
| 右肩绷带不明显，随后又画得过厚、过严实，缺少原著中的渗血感 | 包扎部位、覆盖范围和伤情表现是不同要求；“明显”不等于完整厚护具 | 生成前登记解剖学伤侧、薄血染敷料及露肤范围，和原著、角色阶段、已确认参考一起核对 |
| 02、09、11等镜少指或手型错误；09、11、13反复修左手姿势；21包扎位置也曾错误 | 五指数量、掌背朝向、腕肘连接、包扎范围都要分别检查 | 本节左手保留五指，拇指和食指露出，三根伤指及掌背按定稿包扎；按原尺寸数指并追踪整条手臂，不把本节伤情套给以后所有章节 |
| 埃布尔的蒙面与头部包裹过高、过严 | 必须使用当前剧情阶段的项目设定，不能用通用兜帽蒙面人替代 | 对照实际角色参考，分别核面巾高度、露发、头部轮廓和服装连接 |
| 08把牢房画成矩形，圆牢又出现刻意拉远、尺度别扭；11、12人物跑到牢外；26缺栏杆 | 场景结构、尺度和人物内外位置属于跨镜固定状态 | 先画清小型圆牢的结构与固定柱关系；近景可以只显示局部，不必每镜把圆形全景交代一遍；逐镜连看位置与栏杆连续性 |
| 11击栏姿势缺少力量、人物像被缩放；14出现木桩位置、握持或“虚空搬柱”问题 | 主要动作需要接触、受力和固定关系；试图挤开木桩不能画成已经搬掉 | 检查肩肘腕拳链、拳柱接触、自然人物比例及柱脚固定，保留原著“尝试未成功”的结果 |
| 单镜修好后，其他镜又出现旧错误 | 缺少持续复核的全节连续性记录 | 每次采用新图后回查相邻镜与同场景镜；最终全节检查，不能只看本轮点名镜号 |

这些问题应在分镜确认前解决。用户已经确认的正确手势，进入视频阶段后作为基线保留，不能为了躲字幕又改成抬手、缩人或换动作。

## 2. 成片阶段：字幕、构图和运镜分开处理，造成二次返工

| 出现的问题 | 查明的原因或证据 | 有效修法与以后检查 |
| --- | --- | --- |
| 原版字幕被挪到右下，用户要求固定底部正中 | 为避开伤手改变了用户要求的版式；版式和图稿没有提前联合验证 | 中轴固定，按语义换英文行、微调机位，需要时同尺度重取景；不逐cue缩字、不擅移到右下 |
| 首轮预检通过，实际成片仍有字碰到伤指 | 首中末帧与最长cue并不覆盖所有字句；未越出屏幕也不代表没有遮手 | 全178cue实际像素检查发现片头5条英文遮指，后半12条明确遮手，另有02健康手背和03描边轻擦；以后每cue都检查关键部位，并看每镜首中末 |
| 改倍率后，03指尖仍贴字，甚至向字幕方向移动 | 原焦点在小倍率时触发边界夹紧；配置里的焦点不是实际屏幕位置保证 | 最终改为真正居中的源焦点；15采用右边与底边锁定。记录源焦点、屏幕目标和夹紧策略，看实际编码帧，不能只读倍率 |
| 每镜推进不明显，画面太平 | 用户观感需要实际检查，不能以计划里有zoom当作完成 | 为26镜分别设人物/动作焦点，最终实际编码推进约10–16%，检查首中末、稳定性、脸和关键手部；本节幅度只是参考 |
| 原约1分56秒背景族人重复 | 定位为07镜，后排脸和发型相似，主角检查未覆盖群像 | 区分年龄、脸型、发型和白纹，保留主要人物与场景；以后后排逐人检查 |

本轮实际采用6张新图：07修背景重复；09、13、22、25、26为固定居中字幕和推进作重取景。03、15、16通过机位调整解决，7条英文显式换行，正文含义与时码不变。图像生成候选还出现过请求尺寸与实际输出不符，必须核实际PNG尺寸再采用。

遮挡检查要区分严重程度。伤指、伤掌、主要动作接触点被文字覆盖应修；不影响动作理解的普通衣料、静置副角手套可记为非阻断观察，避免无限扩大重绘。16近景边缘裁入了健康右手的外侧指端，主要左伤手完整、撑地手臂归属可辨；如实记录，不能宣称两手始终全露。

## 3. 配音与声音：整镜合成不等于读词自然

片头原来把Re:0展开成“从零开始”。用户要直接读字母和数字，因此显示稿仍保留Re:0，TTS输入用R、E、零；这应成为后续片头固定读法。

用户还指出人名、普通词中间断开及错读，且没有逐一记录时间点。不能因此等待用户补齐例子才开始，也不能把原因直接写成“按字幕逐条合成”：本次原版实际上是26个整镜语音组，源PCM审查没有发现正文因拼接丢样本，42处专名检查也未发现达到120ms的词内硬静音。这些结果没有否定用户听到的不自然，只说明硬剪接或字幕碎片合成未被证明是原因。

本轮保留冰糖原始预设和默认速度，16组重做、10组沿用，共28次成功TTS请求。先补连续上下文，再试有记录的词组读音覆盖；专名不拆字，覆盖只影响TTS，显示稿不改。辅助语境在正文前句界按24kHz源采样点裁除，保留首词余量；15处切点中10处为零样本、5处为低电平非零，不能笼统宣称全部“零切点”。

自动识别对漏字、近音和时间点有帮助，但“E”转成“一”、“布”转成“伯”不能单独证明错读或读音通过。无静音、PCM连续、响度合格也不等于词流自然。本轮代理音频理解接口返回402，代理没有实际听审；用户随后接受成片另有记录。这两项事实并存。

击栏音效原版也不是完全没有素材：原木响比“砸”字早约360ms，用户听感仍认为缺少。修订后木响对准“砸”后20ms，短冲击层后35ms；木响峰值提高约5.64dB，冲击窗口RMS提高约8.98dB。以后同时检查素材、动作实音锚点、混音后相对人声的强度和实际听感，不能因计划里有event就认定足够。本节数值不作为以后所有打击声的增益预设。

## 4. 版本、验收和交付：必须对应真正交付的文件

- 冻结对象应包括原图、实际相机、ASS、音轨、时间线、分页稿和引用的QA文件。曾因给已引用的图像审查报告追加内容，改变报告哈希，必须重新冻结依赖；只锁媒体不够。
- 早期预检与最终验收分开。`camera-layout-review.json`等历史预检不能因为状态为passed就替代新母版实际审查；确认其输入哈希与对象。
- 全部问题查齐后统一合并，复用未改缓存，减少反复整片编码。只改字幕与画面时，新旧修订候选的解码PCM逐字节相同，证明未连带改音轨。
- 最终六个受影响镜的43cue和18个首中末重新实看；加书签后共45cue新实看、133cue继承，25张阶段/书签帧新实看、60张继承。继承要求图、相机、实际ASS、时码一致、旧实审可追溯，且新旧帧SHA相同或SSIM达标；不能把继承写成“新母版全都重新打开看过”。
- 新分页稿从本版原图、实音时长和相机生成，核26页、溢出与代表页，防止素材包混入旧PDF。已确认的两张封面通过同SHA继承审查，无须重新生成或确认文案。
- 当前平台是Wormhole。MP4与完整ZIP分别冻结；ZIP查完整性和包内MP4。页面确认上传后先关发送端，再用新匿名浏览器真解密下载，核字节和SHA，保存完整含密钥URL、上海时区实际到期及下载次数。单独打开分享页或只下载加密字节不算成功。
- 用户最终接受、代理实际看图、代理实际听审和技术测量分别追加记录；复盘不重打包已交付文件，也不更改原分镜确认。

最终独立技术结果为：完整解码10627帧通过，AAC约−19.02 LUFS / −2.35 dBTP，末镜到片尾无跳回全景；约−18 LUFS是目标，真峰约束下保留固定增益和动态，没有为追目标加入压缩。

## 5. 下一节按这个顺序执行

1. 读当前指针、最新用户偏好、原著和实际角色参考；建立人物/场景连续性表。
2. 生成分镜，逐张数指、追溯肢体、核受力和前后镜；用固定居中字幕与缓推预览安全区。交付完整分页稿，沿用明确的分镜确认流程。
3. 按已确认声线整镜或完整语义组合成，先核片头、专名与普通词，定位问题再选候选；显示稿、语音读法和听审结果分开登记。
4. 用实际音频重排字幕、镜头和声音事件；全部cue与每镜首中末联合检查，先查齐再合并修复。
5. 冻结依赖，出最终母版；核真实编码、音轨、推进、字幕与片尾。改动镜全部复看，未改镜有证据才继承。
6. 同源更新分页稿，核两个平台标题、简介、两种封面、tags和许可，冻结不含视频的素材包；视频完成Wormhole离线匿名解密下载核验，素材通过Gmail实际发送后按两路状态归档。用户接受再另存记录。
