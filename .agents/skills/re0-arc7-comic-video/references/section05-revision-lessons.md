# 第5节分镜与视频返修经验

整理于2026-11-10，覆盖第七章第5节从分镜到片尾读音修复的反馈。展示标题为《一个都不能丢》，原著章节名为“男人很艰苦”。镜号、方位、声音参数和接点均为本节证据；后续章节按实际剧情与机位重新判断。

## 先定位当前采用项和本轮范围

当前执行标准统一维护在[默认规格](production-defaults.md)、[执行规则](execution.md)、[阶段验收](quality-checklist.md)及[交付操作](delivery-and-publishing.md)；本文件按需追溯第5节具体问题，不在每个阶段重复全文加载。

先读本节 `manifest.json`，再沿 `currentVideo`、`adoptedStoryboard`、`pronunciationPatch`、`downloadVerification` 定位实际文件。不能只凭最大的目录编号判断图稿与音频都在同一目录。本节最终视频是 `video-v3-jing4`，采用图稿仍在 `video-v2-bingtang/storyboard.json`，基础分镜确认来自 `storyboard-v6`。

将用户每条反馈登记为“问题—影响镜号/声段—基线—采用候选—验证证据”。跨镜状态变化查完整状态区间；只修一个读音就检查该分句、两侧接点、时序和未改内容。用户要求局部修订时先给对应图、音频或短片，不擅自重做全片；明确要求合入成片时复用已确认素材。已有同版本确认及明确的小修指令不重复询问。

## 分镜问题与生成前检查

| 本次问题 | 以后生成前写清什么 | 生成后怎样判断 |
| --- | --- | --- |
| 08弓手、飞箭和巨蛇留箭的方向与透视混乱 | 固定世界中的发射者、目标、来向；分别登记在途箭与此前留箭，明确哪一支对应旧伤 | 联看上一镜命中点、当前箭尾朝向、蛇身转动和近远缩短关系；不能只修一段箭杆角度 |
| 08已有中箭却像再次刚射中 | 把“此前命中、当前留在体内”和“后续尚在空中”分开写入状态 | 旧箭仍在同一可解释的位置，旧伤黑血附着或流淌；没有新增无依据的爆点、喷血或第二次命中 |
| 08来向应在蛇背后，弓手身份却画得太清楚 | 保留背后入射；射手只作失焦且被树干枝叶遮住的人影 | 不只模糊脸，也检查服装与体型是否暴露后文才应出现的信息；虚化后仍能解释射击方向 |
| 12男主的脚与身体不协调 | 标出负重时的重心、支撑腿、髋膝踝与鞋尖方向 | 从躯干一路追到落地脚，检查关节旋转、受力和地面接触，不能孤立转动鞋子补救 |
| 17背上女孩姿势错误，19出现多手，23机位不该露出两只脚 | 按每个角色分别连接头颈、躯干和四肢，再登记本机位哪些部分可见、被谁遮住；保留原有鞭子固定方式 | 同时检查真实肢体数与当前视角可见数。23镜只露近侧腿脚，远侧被昴遮住；不能为凑齐两只脚凭空添出远侧鞋 |
| 20像浅水，与21水下漂流不衔接 | 连画19起跳、20触水、21被急流卷走，固定水线、落差、水深、入水方向和三人连接 | 本节脚尖先入水，小腿进入水下，脚下不能画成可站立的浅河床；水花向上、气泡与身体向下的关系成立 |
| 15公主抱双手位置不对 | 写出上背与膝后的两个支点，以及每只手来自哪侧肩、肘、腕 | 本节右臂绕雷姆上背，右手接触她上臂；左臂托双膝后下方。手接上袖口仍不够，还要确认实际托住雷姆，不能回到昴自己的肩上 |

手数正确不等于结构正确。15镜第一张返修候选把上方手掌放回了昴自己的肩上，未采用；随后改为更清楚的前方斜侧视角，仍保留原有崖顶、深河和背上的路伊。局部修改无法说明整条手臂时，应重构姿态再连看14、16镜，不持续贴补错手。

本段连续逃亡沿用用户此前指定的伤手不包扎：左手三指受伤，不画成截指；回忆中手健康。此状态须区分时间线，不能写成所有章节永远不能包扎。

## 展示标题和语义必须贯穿生产

首版封面已改为“一个都不能丢”，片头仍念原著章节名“男人很艰苦”。用户随后明确口播也使用《一个都不能丢》。记录原著标题、用户指定展示标题、封面主标题及各自适用范围；原著文件不改，明确的展示标题覆盖相应文字出口，不只修改封面。

生成前后分别核对以下实际产物，而不是只搜索一份计划：

| 出口 | 核对对象 |
| --- | --- |
| 配音 | 真正发出的TTS请求文本、采用录音和片头字幕 |
| 画面与文稿 | 两张封面、逐镜稿、纯口播、中英文字幕和简介 |
| 导出与交付 | 视频元数据、素材包内README与文稿、交付页标题及当前链接 |

23镜按用户要求改为“可她还没恢复意识”，英文对应“she has not regained consciousness”。这里需要保留从入水到上岸尚未醒来的状态延续，不以同义改写丢掉“还没恢复”。中文、TTS输入、英文、图文稿与素材包一起修订。第5节的“英雄”台词也不能画成雷姆恢复记忆，救助过程不能提前画成已完成口对口人工呼吸。

## 环境声、动作声和旁白分别规划

声音事件表至少记录：镜号、声层、空间位置、动作主体、画面时点、旁白锚点、源文件截取范围、起音延迟、相对音量、实际成片证据与许可。

| 本次缺口 | 规划与验收规则 |
| --- | --- |
| 缺少河水背景音 | 从听见远处水声渐入，按崖边、水下、上岸交接，保留合理的空间变化；水下滤波只施于环境层，不施于旁白 |
| 跳河声太轻、像小水花 | 用有身体入水冲击的素材，表现负重跳入深河的体量与尾部水声；同时检查旁白是否清楚及最终真峰值 |
| 缺少咳水声 | 23镜昴呛咳、24镜雷姆咳水分别对应角色、解说和动作，不能提前放到未咳嗽的画面；吐水层与咳嗽层协调 |
| 清单写了音效但成片效果不足 | 既查事件时间，也查源素材从起点到实际声响的延迟；从最终AAC确认声层进入成片。能试听时检查自然度和可闻性，不能试听时明确限制 |

本轮入水效果目标峰值由约-22升至-10dBFS，约增强12dB，这是一次返修的比较，不是后续所有入水声的统一参数。保存单独声层和来源署名，最终混音后重新测响度及真峰值。字幕已确认版式也不因套用产品宣传片清单而擅自改变，仍检查实际字形边界、遮挡和可读性。

## 句末声调与最小音频修复

用户指出片尾“困境”的“境”听成一声，要求第四声 jìng。显示稿保留“困境”，仅本次TTS词组采用同音字“困镜”，沿用冰糖默认音色和速度，不后期移调，不全局替换所有“境”。

1. 先检查原始录音的句末音节与声尾，不能因ASR认出“境”就认为声调正确。正常语义组连续合成；必要时给句末增加辅助语境，让目标词完整发声，再选可分离的候选。
2. 辅助句只是生成材料，必须在实测静音处移除。检查裁接两侧RMS、目标音节是否完整、辅助句是否混入；没有安全接点或新音频超出时间窗时，重算受影响时序，不能硬截、拉伸或挪到片尾字幕之外。
3. 用单一固定增益匹配相邻旁白，只替换对应旁白贡献，保留音乐、环境和动作声。分别核对旁白、带配乐及无配乐冻结WAV的修补区外PCM。
4. 时间轴与字幕未变时复制各版原有视频流，比对video packet及时间戳；字幕文件应逐字节相同。最终AAC再核对同步、降调与声尾，不只看生成前的候选。
5. 需要时提供小体积末句试听，用户不必为一个字先下载整片。实际试听、ASR、音高分析和同步检测分别记录；音高下降受上下文影响，不能单凭固定频率差判定四声或声称已听审。

本轮仅替换末镜最后分句，修补区为404.24至406.5秒，总片长410.5秒。最终AAC测到“境”的音高约194降至159Hz，支持下降调；未实际试听。此频率、接点与增益不作为下次默认。

## 版本、执行和交付中的其他易错点

- 迁移脚本不能只全文替换目录名。第5节曾因 `root + 相对路径` 的旧根目录未被替换，执行时仍指向旧版本；运行前须解析所有写入路径，断言只写本次输出根。服务返回原始WAV与归一化WAV的哈希分别命名，不能把源音频哈希标成采用文件哈希。
- 图片、语音、字幕相对镜内时序和镜头参数均相同的片段可以复用。仅全局字幕文件发生变化，不应自动判定所有镜头必须重新渲染；复用前仍须逐项验证实际字节和局部时序。
- 最新平台是用户因中国大陆下载慢而选择的Wormhole，不使用腾讯或阿里云，不自动回退Litterbox或文叔叔。模板、脚本参考与附件超限处理都须使用同一偏好，不能只更新主技能。
- Wormhole显示“可分享”不等于云端上传完成。等“Uploaded / You can close this page now”，关闭上传端后用独立接收会话核对真实文件列表、下载大小和哈希；各视频版本分别核对。24小时或100次下载是当次设置，每次重新检查，完整保留带解密密钥的分享链接。
- 页面图片替换同时更新原生图片身份，文字变更同步素材包。仅修读音且显示稿、图像、字幕和简介不变时，复用原素材包；只更换新视频入口并按需要补上试听。最终报告、当前manifest和交付页必须对应实际采用版本。
