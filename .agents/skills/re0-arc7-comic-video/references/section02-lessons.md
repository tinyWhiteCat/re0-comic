# 第二节制作复盘：问题、处理与复用方法

本记录整理第七章第二节《Animal Tracking》从原著校对、图稿返修到 2026-11-02 连读片头定稿的经验。最后一次交付为 `video-v8-connected-intro`。下文的镜号、时长、帧数和检测结果都是本节实例，不是后续各节的固定规格。

## 主要问题与处理

| 遇到的问题 | 本次处理 | 后续怎样检查 |
| --- | --- | --- |
| 解说把人物推测写成事实，或省略了行动原因 | 对照原著修订台词：雷姆主动带路伊离开；权能已发动，但没有探知同伴；隐身失效和足迹归属仍保留推测语气 | 分开记录事件、观察和推测。补足因果时须有原文依据，不能用虚构内心戏填补。 |
| 第15镜收剑画成了匕首，剑身与鞘也有连接问题 | 对照第12、14、16镜和原文，采用短剑完全入鞘的动作，核对剑柄、护手、鞘及双手连接 | 同一道具跨镜检查长度、握法和状态，不能只看单张图是否好看。区别蒙面人的短剑与赠给昴的短刀。 |
| 封面武器比例错误，重心偏离昴与蕾姆的关系 | 将两人的情感对立放在主体，蒙面人退到次要位置；4:3、16:9分别构图 | 封面仍须遵守角色与道具设定。关系并置不能冒充本节已经发生的重逢。 |
| 配音显得僵硬、刻意，调整后仍不合用户口味 | 通过短样比较，最终采用用户确认的 MiMo 冰糖原始音色与默认语速 | 音色、语速、读法、停顿分别定位。使用当前确认参数，不为显年轻而继续叠加语气指令、移调或时间拉伸；持续噪声另查来源。 |
| 片头冗长、节号不清，外语简称和多音字读错 | 片头保留 Re0、帝国篇原著解说、第七章和本期节号；显示稿、口播稿与 TTS 输入分别管理 | `原著 → 原住` 只用于特定 TTS 词组；Cor Leonis 口播“狮子心”，首次字幕加拉丁语注释。RE0连读返修见下文。 |
| 声音主要依赖旁白，动作缺少听觉反馈 | 配场景音乐、环境声，并为木棒击中、切枝等实际动作安排音效 | 核对音效与动作或对应台词的时间锚点；音乐和音效有可听见的层次，同时让解说清楚。 |
| 片头时长改变，字幕、镜头、音乐和音效都会受影响 | 按新片头实际长度重算时序，核对未改正文的音频和相对时间后统一平移 | 不能把新音轨接到旧字幕时间线上。只有正文完全不变时，才可用同一个时间偏移量。 |
| 高清文件难交付，临时分享受流量、登录或附件大小限制 | 视频最终用 Wormhole，验证后在聊天给链接；更新后的非视频素材 ZIP 单独邮件发送 | 上传完成、匿名可下载、剩余额度和用户所在地区的体验分别记录。保持1080p要求，不为附件限额擅自降低视频画质。 |

图稿与台词修正后仍按原来的分镜确认流程执行。以上记录不替代每一节的原著核对；第一节的肢体、运镜、字幕和片尾经验继续见[验收清单](quality-checklist.md)与[第一节基线](section01-baseline.md)。

## RE0：读音正确还要连贯

| 阶段 | 实际输入与观察 | 得到的经验 |
| --- | --- | --- |
| v6 | 输入 `Re Zero`，用户要求按字母 R、E 和数字零读 | 先明确用户要的是读法、节奏还是音色，不靠猜测替换简称。 |
| v7 | 输入 `R，E，零`。字母间两处静音各约0.29秒；Whisper对字母片段识别为 `R E`，用户仍反馈太断 | 标点会改变停顿。ASR识别出正确字母，不能证明说话自然。 |
| 短样 | 整句输入 `R E零，帝国篇原住解说，第七章第二节。`，生成4.32秒纯人声。SenseVoice转写为“r一零”，Whisper对超短片段转写为 `Are you?`；用户试听后确认 | ASR对简称、跨语言和极短片段会有误差，不能用转写结果代替用户对读法和节奏的判断。 |
| v8 | 直接复用获批样音对应的WAV，本轮没有新的TTS请求；只做固定增益与首尾留白 | 确认的是这份录音，重新用同一句话合成也可能产生不同读法。应复用已确认源音。 |

SenseVoice为连读样音中 R、E、零标注的token起点分别为0.18、0.42、0.54秒，不等于精确的波形发声起点；另按本次波形检测方法，字母之间未检出超过30毫秒的静音。这些数据用于解释本次变化，不能要求所有简称都达到同一速度或静音阈值。声音是否自然仍需试听。

保留历史检查的原始状态。样音生成时的 `actualListening: false` 表示代理未实际听音，不能改成代理已听审；用户之后的“没问题了，以这种方式重新生成视频吧”另存为确认记录。用户确认源音也不等于已经看过最终混音成片，成片仍须检查同步、音量和编码。

## 将这次经验用于下一轮配音

1. **定位问题。** 分清发错音、字母间停顿、整体语速、音色或背景噪声，保持其他已确认参数。
2. **先做能判断问题的短样。** 遇到新的简称或外语读法、连续返修的停顿问题时，生成覆盖问题词及必要上下文的几秒纯人声核验。用户要求先试听，或读法、节奏仍需用户选择时，交付短样确认后再替换整片；其他情况按已有授权执行。整句连续合成，不拆成单字后拼接，也不先渲染整片来比较候选。
3. **记录具体确认。** 保存显示稿、实际口播稿、TTS输入、模型参数、原样WAV、制作WAV、试听MP3、哈希和用户确认范围。不同格式、采样率的文件分别记录；已经确认的同一录音不重复询问。
4. **复用确认的源音。** 使用试听MP3对应的无损制作WAV，核对哈希。参数确认与本次录音确认分别记录。节号或文字改了，应生成并检查新音频，不能借用这次确认或硬套第二节录音。
5. **再替换、对齐和出片。** 按[局部修复流程](production-pipeline.md#小范围修复与验证)更新时序和素材，验收后再交付；不得把待确认的短样标成已应用到视频。

已确认输入与三份音频的对应哈希保存在[冰糖音色及样音记录](../../../../docs/voice-profiles/mimo-bingtang-default.md)。相同文本可在源文件存在且校验一致时复用；这些本地文件不随技能提交，干净环境不能假定仍有音频缓存。

## 局部替换的同步与验收

本次 v7 片头为151帧，v8将4.32秒的源音加留白后排为114帧，即4.75秒。24fps下差值为 **−37帧，即−1.541667秒**。正文26组、140条字幕和1779条词时间的相对关系未改，因此统一前移；片头之后含片尾的18,998,000个采样、6条混音声部在同一区间的PCM、26个正文及1个片尾底片都与旧版一致。

接入单声道旁白时，片头使用−0.59dB固定增益，源音的采样数量、顺序与内部间隔保留；后续混音另沿用固定增益。最终旁白或AAC文件经过增益、混音和编码，不能声称与原始试听WAV逐字节相同；“源文件哈希一致”“未改区间PCM一致”“成片下载哈希一致”应分别验证。

实际替换时按以下边界处理：

- 新旧版本分目录保存，先冻结输入、确认记录与哈希；不覆盖已交付母版。
- 新片头按实际语音边界加必要留白并整帧对齐；片头字幕重新对齐。正文确认不变后，再平移所有字幕、词时间、镜头起点、音乐段和音效事件，复核动作锚点。
- 缓存复用须核对画面来源、运镜参数、滤镜、帧数和编码规格。时长或烧录字幕发生变化时，重新渲染受影响部分，不能直接把旧成片视频流当作可无条件拼接的素材。
- 局部任务重点查看片头中段、交界前后逐帧及受影响字幕；其余内容只有在源文件和处理链未变、证据充分时才继承旧检查。本次抽看7帧，不是所有任务统一只看7帧。
- 最终文件做完整解码、音画时长、字幕边界、AAC响度与真峰值检查。音频替换无关的应用逻辑未改时，不为此重复运行全套应用测试。

v8最终视频为1920×1080、24fps、9613帧、400.541667秒；最终AAC为−18.03 LUFS、−3.42 dBTP。它说明本次成片通过了对应检查，不要求新片复制这些数值。

## 交付与版本记录

Wormhole链接创建、文件完整上传、关闭发送页后匿名下载核验是不同步骤。完整下载必须匹配本地成片的字节数与SHA-256，分享URL保留 `#` 后的解密片段；有效期、次数和剩余额度每次实查，不能复制旧分享的到期时间。

本次保留1080p视频独立交付，字幕和口播更新后重建不含视频的素材ZIP，再邮件发送。仅更换视频托管平台而素材未变时，不重发已经提交成功的素材。具体平台限制、远程邮件附件和幂等发送流程见[交付参考](delivery-and-publishing.md)。

语音批准、制作完成、文件可下载和邮件API接受分别登记。完成本次交付后，`current-video.json`才指向v8，`current-intro-audition.json`才标记已应用到视频；保留旧版本指针快照。API接受不能写成已确认到达收件箱，临时链接可下载也不能写成已测试中国大陆速度或在线播放。
