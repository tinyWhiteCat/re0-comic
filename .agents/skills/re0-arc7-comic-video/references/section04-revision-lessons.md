# 第四节返修经验

记录于 2026-11-09，来自第七章第4节《勇气的抉择》的分镜与视频返修。下面的镜号、伤势和构图只对应本节；检查方法用于后续制作。历史制作文件在忽略的 `data/` 下，干净 checkout 可能没有，不能把它们当成随技能安装的脚本。

## 先排查全部镜头，再确定修改清单

本次去包扎修订最初列了14镜，完整重合成时直接沿用该清单，漏掉19镜胸前的左手。独立终检在上传后才发现，造成补图、重导出、重打包和重传。问题是排查范围不完整，不是缓存混入旧图。

用户提出“断指不能包扎”等跨镜状态要求时，先建立覆盖全部镜头的表，不从旧修改列表推断哪些镜头安全。

- 从状态发生处查到本节结束或有依据的下一次状态变化。每一镜都填写“需改”“已符合”或“不可见及理由”，不跳过未列入返修的镜头。
- 胸前收拢的手、抱人下方的手、边缘小手和字幕后的手都要查。先看无字幕原图，再看成片实际机位和镜末裁切。
- 删除画面中的处理动作时，同时查口播、双语字幕和音效。本节09镜去掉了固定手指的解说及对应树枝音效，没有编造替代剧情。
- 用户明确的改编要求和原著事实分别记录。本节原文有手巾与树枝固定手指的内容，去包扎是用户要求的改编；不改原著，也不声称原文没有处理。此要求不自动扩展成其他章节永远不能包扎。
- 本节最终修订伤后左手的镜号为09、10、11、12、13、14、15、16、18、19、20、21、22、23、24。这个结果用来解释本次遗漏，不作新任务的预填清单。

## 动作与空间不能分开验收

| 本次问题 | 生成与检查方法 |
| --- | --- |
| 03、06鞭子过短、弧线不自然 | 从握柄和手腕追踪连续鞭身，区分实体、残影与速度线；鞭长、挥臂方向、鞭梢与接触点一致。允许克制的动漫夸张，不用任意线圈代替甩动轨迹。 |
| 09坑先浅后深，人物表情脱离剧情 | 用相邻镜同一坑沿、树根、人物身高、坐姿遮挡及可攀土坡作参照，先统一尺度，再修局部。表情依据当时认知、疼痛与戒备，不只画通用惊讶。 |
| 10强弓威力不明显 | 用箭的路径、撞击点、木屑/泥土飞散及人物反应表现力量；不凭空增加受伤或死亡。 |
| 15推木动作错误，后来又像两只右手 | 双掌抵同一木头后端，肩肘腕和身体前倾共同发力。按角色自身左右核对掌背及拇指侧，不能拿画面左右代替人体左右。本镜采用上方远侧受伤左手、拇指向内朝下，下方近侧健康右手、拇指向内朝上；此姿势不是其他视角的通用手型。 |
| 17扔石头姿势不成立 | 连看蓄力、发力、离手方向；核对肩肘腕、躯干转动、重心及落地脚，石头位置与投掷方向一致。 |
| 21巨蛇威压不足 | 用人与蛇的体量、遮挡、低机位及近远关系形成压迫；保留后续动作需要的空间。 |
| 23贯穿缺乏冲击，24箭角度与黑血错误 | 入射、穿出、箭杆和后续留箭保持同一条可解释的轨迹；接触处、蛇身反应、黑血喷溅及下一镜人物身上的血迹接得上。 |

手部局部编辑后仍要回看整条肢体。两手数量正确不等于左右正确；手指骨折也不等于截指。不要把绷带当成表现受伤的默认图形。

## 固定最新文案与声音偏好

- 原著标题与展示标题分开存。本节原著为“有勇气的抉择”，用户指定展示为“勇气的抉择”；覆盖片头、显示稿、中英字幕、两张封面、简介、元数据、README、压缩包和交付页，不全局改原著。
- `Re:0` 显示不变，口播为 R、E、零；本节修订 TTS 输入为 `R E 零`。ASR 可能把 E 写成“一”，识别文本和技术检测不能代替试听。
- 最新声线是 MiMo `mimo-v2.5-tts`“冰糖”的原始音色、默认速度，不传 style、语速/情绪标签和参考录音。依据第二节 `video-v4-bingtang/brief.md` 的用户确认及第四节沿用记录，覆盖第一节晓晓默认值；不要复用旧片头展开读法。
- 用户先要求局部修订时，只交受影响图、音频或短片；后来明确要求重生成整片时，合入这些已确认修订，未改素材优先复用。只重算受时长变化影响的字幕、镜头、音乐和音效，不为整片导出重新请求全部图像或TTS。

## 修订合入与交付前检查

交付渠道同样必须查实际交付证据。本次先误用早期文叔叔默认，又只读 `direct-email/setup.md` 就把较早准备方案误认成最终方案，并把Resend发信服务当成视频托管网站。后来查实际收到的邮件才确认：视频是Litterbox的1080p MP4直链，素材ZIP经邮件附件单独交付。以后区分视频托管、发信服务与素材附件，以实际结果和用户纠正核验偏好；prepared计划不能冒充已采用或已发送。

1. 收齐当前基线、局部补丁及后续单镜覆盖；每镜只保留一个明确采用项，记录来源、路径和实际字节哈希。本次15镜后出的左右手修正版优先于最早去绷带补丁中的15镜。
2. 渲染前核对采用表、冻结稿、确认记录和时间线指向同一组素材。已有用户授权范围内的漏改直接补修，记录依据；不把它描述为用户已逐张审阅的新稿。
3. 检查原图和成片首中末帧；使用 video-shotcraft 时完成其要求的独立终检。发现阻断项先修复，终检报告绑定最终主片哈希，无阻断后再发送或上传。不同视频版本的最终解码结果分别记录。
4. 成片改了，旧压缩包和已上传链接就不再代表最终版。保留为历史并标记已替代；重建交付包、清单、终检对应关系及下载核验记录。
5. 按渠道核验实际交付结果后再切换当前版本。同步当前视频、采用稿、交付页、附件/链接、修订状态、`fullVideoRebuilt` 和已确认覆盖项；不能一边报告完成，一边保留“未重合成”或 `approved:false`。
6. 更新预览页后读回核对标题、链接、图片引用及完成状态。图片替换同时更新 Markdown 和原生图片 `file_id`，去掉旧图的 blurhash；原生页面没有实际预览时不声称已做视觉检查。

FFmpeg时间戳、缓存和失败即停止的要求见[制作脚本参考](production-pipeline.md)；浏览器缓存、流式下载与取消竞态见[交付参考](delivery-and-publishing.md)。不要在大文件下载变慢时临时堆叠下载实现。
