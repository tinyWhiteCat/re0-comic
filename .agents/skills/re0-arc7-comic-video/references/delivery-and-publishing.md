# 交付操作

本文件只维护当前操作步骤。产物规格和渠道偏好查[默认规格](production-defaults.md)，封面创作查[风格参考](style-reference.md)，完整性查[验收清单](quality-checklist.md#打包与交付)。B站/YouTube发布是独立授权任务，上传网盘不等于发布。

默认视频通过[Wormhole](https://wormhole.app/)，发布素材通过 Gmail。用户明确指定本轮渠道时按本轮授权交付，例如指定用 Wormhole 收素材 ZIP，按同样的匿名下载步骤核验该 ZIP。素材内容与标题格式查[默认规格](production-defaults.md)。邮件只用于用户授权的素材；B站和 YouTube 发布仍按各自授权。历史交付保留原平台、原文件与原记录。

## 打包

制作开始时登记规格、素材范围、渠道、附件上限和许可条件。发给用户的发布素材包按默认三文件清单制作；采用清单、原图、原声、字幕、脚本、配置和检查记录留在内部归档，只有用户明确索取时才另附。额外资料须核许可；禁止单独分发的音乐/音效不附源文件，官方来源与完整许可证据仍内部留存。

1. 视频按 `current-video.json`、素材按 `current-materials.json` 定位采用版；新产物按本轮清单核对。人工核两平台标题、简介、分平台 tags、封面及必要署名，章号、节号和展示节名对应本期。额外资料按授权单列，视频和预览片通过 Wormhole 独立交付。
2. 新包或拟用于新交付的旧包，从仓库根目录执行只读检查。它需要 `unzip`，验证 ZIP 实际条目、CRC、封面尺寸和非空 UTF-8 文案，发布文案内容按上一步人工核对。归档采用包的路径、大小、版本、SHA-256 和检查结果。

   ```bash
   npx tsx .agents/skills/re0-arc7-comic-video/scripts/check-release-package.ts "<发布包.zip>"
   ```

3. 包内封面、文案或必要署名变化，或本轮需要交付的旧包不符合[当前默认规格](production-defaults.md)时，只用当期发布文件重建默认包。保留历史原包和送达记录。内部音轨、字幕或时序更新本身不触发重包，重传视频也不触发素材重寄。阶段工具的历史有效状态只代表已登记依赖和证据有效。

仅修读音而封面、发布文案与必要署名未变时，按哈希复用原发布包，只更新视频入口。内部清单绑定新视频哈希时只更新内部清单，不因此给用户增加文件或重寄未变发布包。按需要单独提供短试听；重新封装、重编码画面与重新请求素材分别记录。

## 短样交付

需要用户评价短样或候选时，先提供真实可访问的试听入口，并按对应渠道核验；不能只说“已生成”或给内部路径就开始询问。用户反馈没有收到时先检查交付入口与记录，不记为试听或批准。用户选择只覆盖实际听到的候选与明确范围，不扩大为整片接受。

候选标明编号、实际源音与片段范围，需要选声时先单独播放，再加入同一段旁白/配乐，排除旧目标音效。已批准录音按哈希复用，不重复请用户判断；来源、许可和实际选用范围留档，不把官方预览写成原始母带。

## 上传与核验

1. 先核对网络策略、代理与CA信任，检查平台当次登录、容量、保留期及下载次数条件；若有次数限制，为匿名验收和用户下载各保留至少一次。优先可用官方连接器，能力不足才用浏览器，不假设历史访客额度永久有效。
2. 核对源文件字节数/SHA-256再上传。官网确认云上传完成并允许关闭发送页后关闭该页；若实际采用要求发送端在线的直传，记录并满足此条件，不标成已完成云存储。创建链接或进度条不等于文件已可独立下载。
3. 新匿名上下文打开完整分享链接，保留`#`解密片段，等真实文件列表就绪后实际下载、解密整文件一次。比对解密后文件与本地源的字节数/SHA-256；若站点另打ZIP，检查目录并核对其中目标文件，密文或外层ZIP哈希不能代替目标文件校验。失败定位到具体请求，不无条件重复上传/下载。
4. 核验后记录当次保留期、下载上限及实际剩余次数；站点未提供的值写null并说明，不把上限100次推算成核验后剩余99次。历史24小时/100次不是固定承诺。没有精确服务端到期时间就注明采集时间与预计到期，使用北京时间；次数耗尽可提前失效。
5. 私有交付记录保存文件名、路径、版本、字节数/SHA-256、完整URL、核验时间、期限、次数、密码或接收条件（如有）、预览能力及下载解密校验结果。完整含`#`的URL仅存私有记录及授权渠道；回复用户时保留完整链接。未测站内播放/大陆速度不承诺。链接过期从保存文件重传，不重新制片。

证书错误先修受支持的信任设置；历史可用Playwright路由经继承代理/CA的undici请求后fulfill，但不能关闭TLS验证、绕过代理或把Cookie/令牌写入公开记录。付费、登录或新平台凭据确为必要且未授权时说明限制，不擅自购买。

当前采用项从本节manifest/current指针定位，不把首次转存记录当成后续修订版。主片、无配乐版、720p版逐项保存大小、哈希、URL与独立下载结果；不能以主片校验代替其他版本。视频超出Page附件限制时仍沿用Wormhole，不自动回退旧平台。浏览器必要时可使用仅限本会话、仍校验TLS的HTTPS/WebSocket转发；保持代理与CA，不擅改永久信任。加密分块由Wormhole官方页面处理，不能把密文当成MP4交付。

大文件不要经route.fulfill整包转成base64；普通小响应可使用已验证转发。下载只保留一个写入者，取消后确认请求、文件流和旧进程已退出再复用路径。最终大小与哈希以实际落盘文件为准；Wormhole前端解密完成后才是可校验原片。

仅在需要排错时参考本地 `data/productions/chapter070/section06/video-v2-re0-intro/delivery-qa/wormhole-browser.ts`：它按清单核对字节数和哈希，只适配当次目录，位于忽略目录，干净checkout可能没有。2026年11月11日实测，正常验证证书的Node HTTPS转发若以chunked方式发送B2二进制上传请求，会返回400并使Wormhole退回直传；按实际body字节数显式设置 `Content-Length` 后云上传成功。官方接收页在Service Worker不可用时有Blob下载后备流程，仍可通过官方按钮下载解密，无需关闭TLS校验或改写下载逻辑。

## 仅素材邮件

1. 使用 Gmail 发送素材，核对已授权的发件账户、收件范围、ZIP 哈希及回执。先查本节私有交付配置或会话记录，缺收件人时再询问。相同包已有发送接受回执则直接引用；状态不明先查已发送记录。实际发送前按[打包检查](#打包)核当前包。打开 ZIP 内的发布文案，用最终混音清单核必要署名；包与用曲均沿用已核版本时可复用该记录。以本期版本、收件人和包 SHA 作防重标识。
2. 按当前 Gmail 工具字段添加真实附件；有 `attachment_files` 时传本地绝对路径。按实际限制核大小及编码开销，超限时先尝试保持画质及尺寸的无损优化，再核包。默认三文件 ZIP 作为一个附件；额外资料按授权拆分。Gmail 暂不可用或默认包仍无法发送时记录实际阻塞，沿用当前渠道。
3. 正文列出可复制的 B站标题、YouTube 标题、简介和分平台 tags，附已核验的默认 ZIP。必要署名留在简介末尾，额外资料按授权单列。视频、预览片和链接在聊天中交付。
4. 用户已授权本次完整交付且账户、收件人与素材范围明确时直接发送，不增加例行确认。创建/保存草稿只记“草稿”，不是已发送；私有记录保存真实发送动作的接受时间、Gmail消息/线程ID、收件人、授权范围、附件清单和包SHA。API接受不等于已验证到箱，历史Resend回执不代替本次Gmail发送证明。
5. 工具支持时读回已发送邮件，核对收件人、主题、正文、附件名/大小；必要时核附件内容。分别记录未发送、草稿、发送接口接受、已读回发送邮件及实际到箱状态，未验证项不冒充完成。邮件内容变化才更新素材包或补发变化项，相同素材不因视频重传而重复发邮件。

## 完成交付

核实实际交付结果后，更新对应的 `current-video.json` 或 `current-materials.json`，登记实际渠道与回执，并保存旧指针快照。仅产出封面或制片内部验收时，记录相应采用文件和实际范围。完整交付分别核查视频与素材，局部交付按本轮范围记录。最终回复提供实际交付链接或邮件状态，以及适用的规格、时长、期限和次数。邮箱、密钥、临时链接和回执留私有记录。

以前文叔叔流量不足、tmp.link登录要求、旧双邮件方案、Resend远程附件及大Base64请求失败的细节见[旧交付经验](delivery-history.md)，正常任务不读取，历史替代渠道不作为当前默认。创作标题格式与简介不在本文件重复维护。

Page图片换版同时更新Markdown及原生file_id，移除旧blurhash；附件返回结果未知时先查已有文件，避免重复上传。写入后读回当前标题、采用图片、完整视频链接和完成状态，没有原生预览不声称视觉检查。
