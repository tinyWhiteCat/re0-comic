# 交付、封面与简介

## 分镜审稿与成片交付

制作分两阶段：先交付按镜号排列的彩色分镜图、逐镜解说台词、转场与预计时长，提供用户能打开的预览或下载入口；用户明确确认当前版本后，再制作视频。审稿材料准备好时只报告“分镜待确认”，不报告整期完成，也不提前运行正式配音、混音或视频渲染。

记录用户确认的版本和范围，已有同版本确认无需重复询问。剧情、主要画面、顺序或台词含义有实质改动时，交回受影响内容复核。最终四项交付仍按下文执行；分镜确认不能代替封面文案审核。

## 文件与版本

使用当前节专属目录，避免覆盖第一节或其他已确认版本。每次采用新图、新台词或新成片时，记录来源版本、改动范围、实际文件路径、尺寸/时长、字节数及 SHA-256。旧候选不必全部发布，但应能追溯为什么采用当前版本。

完整制作一集必须交付以下四项。文件名为建议，交付清单应记录实际路径：

| 产物 | 默认规格 | 建议文件名 |
| --- | --- | --- |
| 视频 | 1080p、16:9，含配音、双语字幕、音乐音效和片头片尾 | `video-1080p.mp4` |
| 封面一 | 4:3，1280×960，单独适配构图 | `cover-4x3.jpg` |
| 封面二 | 16:9，1280×720，单独适配构图 | `cover-16x9.jpg` |
| 视频简介 | 经 Humanizer-zh 润色、可用于 B站和 YouTube 的 UTF-8 中文简介 | `description.txt` |

两张封面使用同一套已确认文案，分别排版。同一张封面的 PNG、JPG 两种格式不算两张。简介必须保存成文件，不能只写在聊天里。四项齐全并通过检查后，才能报告本期完整制作已完成；局部修订按用户指定范围执行。

另外归档双语 SRT/ASS、纯口播稿、音频来源说明和两张封面的 PNG 原图。720p 成片及无配乐版按需要单独提供下载；无配乐版文件名应说明是否保留音效。

素材 ZIP 只包含封面、简介、字幕、口播稿和说明清单等非视频资料。1080p、720p、无配乐版、预览片等所有视频均单独交付，不放入素材压缩包。打包时明确列出素材文件，打包后核对压缩包内的实际文件清单，避免将整个交付目录中的视频一起收进去。

每次改片头、台词或配音时长，都要重新核对字幕时间、口播稿及包内清单。即使两张封面没有变化，只要这些文件已变，就应生成并核验新的素材包。仅更换视频托管平台或重传同一原片时，素材没有变化则沿用原包和已有发送回执。

大型媒体和缓存存入仓库忽略的 `data/`，文稿、配置、生成记录放入 `docs/productions/`。供画廊展示的精选彩图沿用 `public/comics/`。新增技能文档应能被 Git 收录，不能因为技能目录被忽略而漏掉。

## 当前交付方式：视频链接与素材邮件

2026-11-02，用户在试传成功后确认后续视频默认上传到 [Wormhole](https://wormhole.app/)，无需每次重新确认平台。核验后直接在聊天中给下载链接，不再发送视频或视频链接邮件。只有不含视频的素材 ZIP 发到当前会话已授权的邮箱。收件地址、凭据和私有发送回执保存在本节忽略目录，不写进公开文档。

用户要求的是 1080p 原片。邮件附件容量或旧平台流量不足时，通过已授权的文件托管解决传输，不擅自改寄 540p、720p 或压缩后的轻量视频。保留原片、原时长和完整音轨；只有用户另行需要预览时，才单独提供并标明轻量版。

本轮第二节连读片头版的交付记录为 `data/productions/chapter070/section02/video-v8-connected-intro/delivery-latest.json`：288,939,907 字节的 1080p 原片已在 Wormhole 完整下载并通过哈希核验，新的无视频素材包邮件获 API 接受，没有发送视频邮件。后续交付应读取当前制作版本的实际清单；v6、v7 和短试听的链接、时限及发送记录只用于追溯，不能替代新版结果。片头修订与样音确认的经验见[第二节制作复盘](section02-lessons.md)。

Wormhole 每次先核对源文件版本、字节数和 SHA-256，再上传。只有官网显示上传完成并允许关闭发送页后，才关闭该页，用新的匿名浏览器上下文重新打开完整分享链接并下载整份文件；核对实际字节数和 SHA-256 与源文件一致。第二节 v7、v8 和短试听均完成过这条核验链，相关证据位于各自的 `delivery-qa/wormhole/`。创建分享链接或显示上传进度不等于文件已可独立下载。

v7、v8 当次均未登录、未付费，页面设置为 24 小时和 100 次下载，校验后剩余 99 次。这些只是当次观察，不是固定服务承诺。每次重新核对账号条件、保留期、次数上限及校验后的剩余额度；达到下载上限也可能提前失效。没有读到精确服务端到期时间时，按当次记录说明“预计到期”，用北京时间表达，不复制旧版的绝对日期。云环境完整下载成功不证明中国大陆线路速度；未核验站内播放时明确写“未测试”，不承诺在线播放。

Wormhole 分享链接包含 `#` 后的解密片段，交给用户时必须完整保留，不能只复制前半段。完整链接及其解密信息只保存在本节忽略目录和已授权的交付渠道，不写进公开文档。平台受阻时说明实际卡点，保留原片，不把创建链接当作文件上传完成。

本次 Chromium 证书库不可写时，使用 Playwright 路由把 HTTPS 请求交给继承环境代理和 CA 信任的 `undici` 执行，再将响应交回浏览器 `fulfill`。这仍须保持 HTTPS 证书验证与原有网络限制；不得关闭 TLS 验证、绕过代理或更换网络路径规避访问限制。

素材邮件与视频托管分别记录。v6 只更换托管平台时，素材未变，沿用原回执而不重发；v7、v8 修改片头后，字幕及口播文件随之更新，核验新包后分别寄送。按文件和包的实际版本、哈希判断是否需要新邮件，不因“只是改片头”就漏发更新后的字幕，也不因重传视频而重复寄同一素材。

此安排取代此前文叔叔默认上传及“视频链接、素材各一封邮件”的方式。下列旧平台流程只用于追溯和经用户授权的后续选用，不作为当前默认，也不自动恢复视频邮件。

本轮曾先探索 [tmp.link](https://www.tmp.link/)。当次上传入口要求账号，环境没有配置该站点上传凭据，因此没有上传文件；用户随后改为尝试 Wormhole。此记录不代表 tmp.link 已托管本期视频，也不据此推广该站点其他入口的条件。

## 文叔叔交付（历史）

用户曾指定视频使用 https://www.wenshushu.cn/。当时分别提供视频和素材包的下载入口，并逐项记录下载位置和核验结果。以下为该阶段的上传与核验流程；网站上传本身不代表授权发送站内信或发布到视频平台。

1. 核对待上传版本，计算字节数、SHA-256 和时长，使用能识别章节与版本的文件名。
2. 优先用可用的官方连接器；没有上传能力时使用浏览器。先查看当前页面和上传限制，不假设访客额度、保留期或按钮名称永久不变。
3. 选择文件，核对名称与大小，完成上传并保存成功页及分享链接。访客分享若不需要收件人，保持收件人为空。
4. 用新的匿名浏览器上下文打开分享链接，等待真实文件列表显示后下载。不要在加载骨架仍显示时点击下载，以免得到意外的空包或打包结果。
5. 对下载文件计算 SHA-256，与本地上传源比对。若网站返回 ZIP，检查目录并核对包内目标文件，不能把 ZIP 的哈希与原 MP4 比较。
6. 保存交付记录：平台、文件名、路径、大小、哈希、分享页 URL、核验时间、实际有效期、提取码要求、在线预览能力、下载核验结果。
7. 最终回复给用户可访问的分享链接和实际有效期。到期时间按用户所在的 Asia/Shanghai 时区表达；没有准确到期时间就照页面写“约 24 小时，以倒计时为准”。

第一节访客上传实测约 24 小时有效、无需提取码、仅支持下载。这是历史观察，每次仍以页面为准。不要承诺在线播放，也不要把历史链接当作永久素材地址。

2026-11-02，第二节的 1080p、720p 分享在匿名下载校验后，用户均遇到“分享流量不足”。官方说明，对方预览或下载大文件会消耗发送方的分享流量；接收者已有的赠送或购买流量也可能用于下载。校验下载同样消耗额度，一次下载成功不能证明还有足够额度供用户下载。没有证据时，不断言是校验耗尽了全部额度，也不保证登录、重传或等待半小时就能恢复。

当时官方[帮助中心](https://www.wenshushu.cn/help)把超过 50.00 MB 的文件列为大文件，[商城说明](https://www.wenshushu.cn/ag/hl?prod=com.wenshushu.web.pc&page=mall&lang_id=vzh27qqwmc)写明“小文件不会消耗分享流量”。制作小于 45,000,000 字节轻量版是该阶段的排查尝试；用户明确要求 1080p 后，应保留原片并更换已授权的传输方式，不能用轻量版代替。不要拆分文件或轮换账号规避配额；用户另需轻量预览时如实标注画质压缩，且仍不放进素材 ZIP。

上传前检查当前流量规则；大文件如需整文件回读，先考虑校验与用户下载需要的总额度。保留真实校验结果和用户后续报错，不能把云环境可下载等同于用户所在地区始终可用。若付费、登录或换平台仍是必要条件，说明具体限制，让用户选择，不擅自购买流量。

仓库本地曾使用 `data/productions/chapter070/section01/keyframes-v5/video/continuity/wenshushu-browser.ts`，这是忽略目录里的临时 Playwright 辅助脚本，干净 checkout 可能没有。它不是网站 API，也不是本技能自带的稳定依赖；缺失时用当前浏览器工具，或按需要编写 TypeScript 自动化。

云环境联网前按环境技能读取网络策略，继承代理与信任配置。证书错误先排查受支持的信任设置；不为上传关闭 TLS 校验，不把登录 Cookie、上传令牌或浏览器用户目录写进交付记录。

上传受阻时保留本地成片并准确说明卡在哪一步；优先修复本次连接或上传。用户要换平台时再按其要求处理。链接过期只需从已保存的成片重传，无需重新生成画面和音频。

## 邮件交付的历史经验

2026-11-02 较早的交付中，用户为第二节选择邮件接收，并明确要求视频为1080p原片；在分卷附件和原片下载链接之间，选择了“邮件里放高清原片下载链接，不用文叔叔”。当时采用一封邮件放已核验的原片链接，另一封邮件直接附不含视频的素材ZIP。此双邮件方式已被上面的“只寄素材邮件”要求取代。用户要求1080p时，不能为满足附件大小限制擅自改寄540p或720p版本。历史邮件方案与单次发送记录保存在本节的忽略目录中，不把收件地址、密钥或私有回执加入公开文档。

Resend 的 Sending access 密钥已足够完成素材邮件发送，不需要 Full access。此前大体积内嵌 Base64 附件请求遭云环境密钥代理 401 拒绝，而相同密钥的小请求成功；采用官方远程附件格式 `attachments: [{ filename, path }]` 后，素材邮件获 API 接受。根因没有完全确认，不把这次现象推广为固定的代理大小上限，也不因它要求扩大密钥权限。

远程附件的 `path` 必须直接返回无需登录、无需前端解密的 ZIP 字节，不能填写普通分享页面。先上传素材包，再匿名完整下载并核对字节数、SHA-256 和 ZIP 内无视频，才把该 URL 交给 Resend 取回并加入邮件附件；抓取时链接仍须有效。第二节 v7、v8 使用 Litterbox 暂存约 9.4 MB 的素材 ZIP，作为这一流程的传输示例。Litterbox 的规则仍需当次检查，它不是视频默认平台，也不据此恢复视频邮件。

发信前核对会话授权的收件人、素材版本和已有回执，保存文件哈希、内容指纹及稳定的 `Idempotency-Key`。相同素材已有接受记录时不重寄；网络结果不明确时先查请求记录，不盲目再次发送。新版本应有对应的新内容指纹和发送记录。

邮件 API 接受与最终投递到收件箱是不同状态。私有记录中保存 API 邮件 ID、收件范围和接受时间，回复只说明实际确认的状态，不声称未核实的到箱结果。既有素材邮件授权不自动扩展到其他收件人。当前交付概况与详细上传、下载及发送证据分别归档；公开文档不写实际分享 URL、解密片段、邮箱或回执 ID。

## 封面

先从本期真实冲突中拟短主标题，给用户 review 后再生成；已经批准的文案不重复确认。情感落差来自人物认知或关系的变化，不能以虚构死亡或过度宣称杀意吸睛。

保留三层文字：系列名、本期节号/节名、主标题。第一节最终示例是：

```text
Re:0 帝国篇
原著解说 · 01《洗礼》
她醒了
英雄成了敌人
```

此文案只对应第一节，后续各节重新依据内容拟定。完整制作默认同时交付 4:3（1280×960）和 16:9（1280×720）各一张，分别排版。平台规格以发布时要求为准，用户指定其他尺寸或两种不同创意时按本次要求调整。视频仍为 16:9，不能因封面尺寸调整而改动成片。

生成后实际查看图片，逐字核对节名、引号、主标题和字体残影；检查人物身份、面部比例、头顶裁切、文字安全边距及右下方平台时长标记的空间。改标题时不无故改副标题和人物；改比例时重新构图，不拉伸人物或简单裁掉字。

通过图像工具生成/编辑，保留提示词、参考图和版本记录。FFmpeg 等工具可做尺寸和编码导出，导出后验证实际宽高、纵横比、大小和哈希。不能用文件名声称图片已经达到目标比例。

## 视频简介

先用一两段讲清本期人物冲突，再说明这是《Re:从零开始的异世界生活》第七章帝国篇原著解说、所覆盖的小节及呈现方式。必要标签少量附后。完整制作时将定稿保存为 UTF-8 的 `description.txt`，纳入交付清单，并在回复中展示正文或提供文件链接。用户单独只要简介时直接交付文案，不自动改视频或发布到平台。

口播稿的详细剧情不必全部塞进简介；简介也不能超出视频讲述范围。沿用 Humanizer-zh，保留不确定性，避免空泛宣传与“震撼来袭”等没有信息的词。

B站或 YouTube 发布是独立任务。只有明确得到发布指令后，才使用对应账号执行；网盘上传完成时只报告“已上传供下载”。
