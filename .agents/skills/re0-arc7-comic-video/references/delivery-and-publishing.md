# 交付操作

产物和渠道按[默认规格](production-defaults.md)，验收结果按[分阶段验收](quality-checklist.md#打包与交付)记录。B站和 YouTube 发布各自需要授权。旧平台和历史故障按需查阅[旧交付经验](delivery-history.md)。

## 打包

1. 按 `current-video.json` 和 `current-materials.json` 找到采用文件。尚未登记的产物查本轮清单。人工核章号、节号、展示节名、封面、两平台标题、简介、各自 tags 和必要署名。默认包内容及额外资料的许可要求见[默认规格](production-defaults.md)。
2. 新建或拟复用的发布包从仓库根目录运行以下只读检查。命令依赖 `unzip`，核 ZIP 条目、CRC、封面尺寸及非空 UTF-8 文案。归档采用包路径、版本、字节数、SHA-256 和结果。

   ```bash
   npx tsx .agents/skills/re0-arc7-comic-video/scripts/check-release-package.ts "<发布包.zip>"
   ```

3. 封面、文案或必要署名变更，或旧包不符合本轮规格时，按当期文件重包，保留历史原包及回执。包内容与规格都未变时按哈希复用，读音、字幕、时序或编码返修只更新视频及相应内部清单。

## 短样交付

先提供真实可访问的试听入口，再请用户选择或评价。依渠道核验入口，用户未收到时先检查链接和回执。只记录确认过的候选及范围。

标注候选编号、实际源音和片段。选声先听单独音轨，再放进同一段旁白和配乐，排除旧目标音效。经确认的录音按哈希复用，留存来源、许可和用段，区分官方预览与原始母带。

## 上传与核验

1. 按本轮授权选渠道，用户指定以 Wormhole 交付素材 ZIP 时也走以下下载核验。检查网络策略、站点当次的登录、容量、保留期和下载限额，受限时为匿名校验和用户取件各留至少一次。优先用有相应能力的官方连接器，缺少能力时用浏览器。需要尚未授权的付费、登录或凭据时，说明具体限制。
2. 计算源文件字节数和 SHA-256。确认官网完成云端上传后关闭发送页。若当次为须发送端在线的直传，保持在线并记录该条件。 [Wormhole 官网](https://wormhole.app/)
3. 用新的匿名浏览器会话打开含 `#` 解密片段的完整链接。等待官网列表就绪，由官网前端整文件下载、解密，与源文件逐一比对字节数和 SHA-256。官网若另打 ZIP，核包内目标文件。主片、无配乐版和 720p 等各版本分别核验。
4. 私有记录保存文件名、路径、版本、字节数、SHA-256、完整 URL、核验时间、结果、取件条件和实测预览能力。记录当次保留期、下载上限和实测剩余次数，站点未给出的值填 `null` 并说明。缺少精确到期时间时记采集时间和北京时间预计到期，注明次数耗尽可提前失效。链接过期从已保存的文件重传。

取件失败先定位官网当次的上传与实际存储域、官网接收页使用的下载端点。本机转发和测试文件只用于排错。证书出错先恢复受支持的 CA 信任。仍需转发时沿用当前会话的代理和 CA，保留 HTTPS 或 WebSocket 的 TLS 证书链及主机名验证，凭据留在会话内。

需要转发分块时，按每个上传请求实际发送的字节数设 `Content-Length`。若 B2 转发用分块传输后返回 400 并退回直传，先比对请求体与此头的长度。接收按官网本次请求的存储域与分块转发，逐块记实收字节和完成状态，有响应长度时对照。大文件流式或分块处理，小响应可用已验证的 `route.fulfill`。下载只保留一个写入者，取消后确认请求、文件流与旧进程均退出。由官网按浏览器环境选下载方式，Service Worker 不可用时官网可自行使用 Blob。 [第 28 节排错记录](../../../../docs/productions/chapter070/section28/retrospective.md#封面与交付)

## 仅素材邮件

1. 发送前查本节私有配置或会话记录，核对 Gmail 发件账户、用户已授权的确切收件地址及素材范围。历史地址用于追查授权，查不到本次地址时才补问。同版本、同收件人、同 ZIP 哈希已有接受回执时复用，用户明确要求重寄时按本轮授权操作。状态不明先查已发送。
2. 从当前采用记录取 ZIP，等待期间若采用版更新则重新取包。核对即将附上的文件名、字节数、SHA-256 和包内条目。打开 ZIP 内的发布文案，用最终混音清单核必要署名。 [打包检查](#打包)
3. 正文给出可复制的两平台标题、简介和各自 tags，必要署名在简介末尾。默认 ZIP 作为一个真实附件，额外资料按授权另附。按当前 Gmail 工具字段提交附件，有 `attachment_files` 时填绝对路径。按实际限制核附件大小和编码开销，超限可试保留尺寸的无损优化，再验包。仍无法发送时记录阻塞。视频、预览和视频下载链接在聊天交付。
4. 工具支持时，从 Gmail 已发送读回收件地址、主题、正文、附件数量、文件名和字节数。可取回附件且需要核对字节时加验哈希。私有记录保存发送接受时间、消息和线程 ID、收件地址、授权范围和附件证据，区分草稿、发送接口接受、已发送读回和接收端证实。视频重传沿用已核实的素材回执。

## 完成交付

按本轮范围核实交付后更新对应 `current-video.json` 或 `current-materials.json`，记渠道与回执，保存旧指针快照。只有本地采用文件时记录文件及实际范围。回复给出完整下载链接或已核实的邮件状态，以及适用的规格、时长、期限和次数。邮箱和私有回执留内部，临时下载链接只发获授权的渠道。站内播放、地区速度和收件箱到达情况按实测或接收端证据报告。

Page 图片换版时更新 Markdown 和原生 `file_id`，清除旧 `blurhash`。附件结果不明确时先查已有文件。写入后读回标题、采用图片、完整视频链接和完成状态，原生预览按实际检查情况记录。
