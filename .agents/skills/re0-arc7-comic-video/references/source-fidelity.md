# 逐镜原著对应与校对

本规则复用现有分镜JSON中的 `source`、`sourceSha256`、`sourceLines`、`sourceNotes`、`narration` 和 `frameDescription`，不另抄一份长台词表。新增信息仍写在同一JSON中；任务brief只引用文件路径。旧批准稿不原地改写，也不因补字段自动获得新确认。

## 本节只建立一次的资料

在分镜JSON中增加 `sourceMapping`：

- `documents`：本节及必要前文的 `id`、仓库相对路径 `file`、实际文件 `sha256`、少量原文锚点 `anchors`。锚点含 `id`、连续原文 `quote`，可附1起始且含末行的 `lineRange`。只摘定位需要的短句，不复制整章；文件哈希防版本漂移，锚点定位内容，行号用于快速查找。
- `events`：原著顺序排列的关键事件，每项含 `id`、简述 `summary`、`sourceRefs` 和承载它的 `shotIds`。某段被合并讲述时注明合并到哪镜，不为凑镜数补剧情；回忆/现实与原著有意省略的过程保留。
- `states`：本节当前阶段的人物认知、身体状态和持有物，每项含 `id`、`description` 和 `sourceRefs`。名称体现适用阶段，回忆与现实不要共用含义不同的状态。状态变化再建新条目，逐镜引用，不每镜重抄。

引用写作 `文档id#锚点id`。原著事实与人物判断分别归因；不知道、忘记、误以为、推测和确知不可互换。单靠角色设定图不能推断认知、伤势或持有物。

## 每镜五项信息

在既有 `shots[]` 内增加 `sourceReview`，保留现有台词和画面字段：

| 字段 | 内容 |
| --- | --- |
| `sourceRefs` | 支持本镜的实际原文锚点；需要跨前文时列出额外来源，不能只挂一个无关行号。 |
| `mustKeep` | 必须保留的事件、因果和对白含义，非逐字对白用转述。 |
| `knowledge` | 引用本节states中的id，说明此镜适用的人物认知/身体/道具状态；无人物镜可为空，不能强行制造内心戏。 |
| `visualRequirements` | `{description, basis, sourceRefs?, decisionReference?}`，区分 `explicit`（原文明写）、`staging`（合理具象化）、`user-direction`（用户要求）、`continuity`（采用图连续性）。前三项之外的设定图引用也放decisionReference，不冒充小说段落。 |
| `forbiddenAdditions` | 本镜不得新增或提前的心理、结果、人物、道具；无额外限制可为空，不为了填表编造约束。 |

原文明写的visualRequirements必须有可查原文。用户要求、连续性和具象化要求必须写 `decisionReference`，指向反馈、设定图、采用图或本镜演出决策记录；“合理具象化”不是增加新情节的许可。所有要求仍需人工核对是否与事实相容。

`eventIds`另列本镜承载的events标识，与events中的shotIds双向对应；这是索引，不再抄一遍事件描述。

校对状态用 `status: pending | reviewed`。人工完成生成前校对后，将当前 `narration` 与 `frameDescription` 的UTF-8字符串SHA-256分别记为 `checkedNarrationSha256`、`checkedFrameDescriptionSha256`。字句或画面描述变化后旧校对失效，不能复制reviewed标签放行。原图生成结果另做实际看图检查，此状态不代表图已画对或用户已确认。

## 第三节历史经验怎样应用

| 镜头 | 应明确的边界 |
| --- | --- |
| 14：防备机关 | 原文说明继续追踪和处理机关；停在草结前、双手撑膝属于已采用的具象化演出，不声称原文逐字规定这个姿势。画面不能误读成已经踩中机关。 |
| 18：高枝扑击 | 从高处向下扑击有原著依据；机位与倾角是演出选择。双腿限制需引用相关状态的前文依据，不能只用扑击段行号证明她所有身体情况。 |
| 24：质问 | 原著质问抛弃幼女的行为；她不知道路伊的罪，不能写成她曾知道但忘记，也不能因讲述路伊而把本人凭空放进当前对话画面。 |
| 01：查看架后 | 架后清洁遗漏来自原文；柜子不搬来自用户后续要求。二者分别标注，不能用已确认构图覆盖原文措辞。 |

角色设定、用户要求与视觉正例的来源区别见[最终案例](confirmed-cases.md)；画面与解说质感见[风格参考](style-reference.md)，这里不再复制。

## 两次检查，各有范围

1. **生成前**：人工核对“原著→分镜”的关键事件覆盖，以及“解说/画面→原著”的每项具体陈述与因果；查人物知情边界、身体状态、引语/转述和演出新增。填写reviewed及文本哈希，再运行结构检查。尚有语义疑点时标pending，不用字段齐全冒充通过。
2. **生成后**：实际看图核对动作、空间、表情、人体/道具与已定要求是否一致。仅修绘制错误时不重读整章；台词含义、剧情或画面方案有实质变化，重开对应镜及邻镜的原著校对。跨场景/全节事件顺序变化时才扩大范围。

原著文件变化时先查差异，重新核对受影响锚点、状态与镜头，再更新版本和证据；不为了让脚本通过直接改写文件哈希。用户确认仍绑定实际图文版本，结构检查不能代替确认。

## 结构检查工具

从仓库根目录执行：

```bash
npx tsx .agents/skills/re0-arc7-comic-video/scripts/check-storyboard-sources.ts data/productions/chapter070/sectionNN/storyboard.json
```

默认源文件相对当前仓库目录，另有 `--root ROOT` 指定来源根目录。分镜保存sourceMapping和上述sourceReview后才能使用；旧格式会明确报缺项，不静默当作新规则已通过。新制作在生成图像前执行，实际语义仍由Agent读文核对；旧已批准产物不为迁移此结构而重新生成。

工具检查原文哈希、锚点原句及可选行号范围、引用是否存在、关键事件是否挂到实际镜号、事件与镜头是否相互引用、状态引用、五项字段及reviewed是否绑定当前文稿。它不会判断作者是否遗漏了关键事件、引用是否真正支持叙述、知情边界是否正确，也不进行图像或听感判断。把其报告与分镜JSON作为storyboard阶段检查输入，详细原始依据保留本地；不要对未校对的镜头预填reviewed。
