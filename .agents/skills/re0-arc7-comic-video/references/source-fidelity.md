# 逐镜原著对应与校对

在现有分镜 JSON 补原著依据，沿用 `source`、`sourceSha256`、`sourceLines`、`sourceNotes`、`narration` 和 `frameDescription`。任务摘要引用文件路径。批准仍绑定当时的图文版本。

## 本节只建立一次的资料

在分镜 JSON 中建立 `sourceMapping`。

- `documents` 登记本节和必要前文的 `id`、仓库相对路径 `file`、文件 `sha256` 和 `anchors`。锚点只摘定位用的连续原文 `quote`，给出 `id`，可附 `lineRange`（第 1 行起算，含末行）。
- `events` 按原著顺序列关键事件的 `id`、`summary`、`sourceRefs` 和承载它的 `shotIds`。合并段落标明承载镜，区分回忆与现实，保留原著留白。
- `states` 用 `id`、`description`、`sourceRefs` 记录人物认知、身体状态和持有物。按阶段和状态区间命名，变化后另立条目，供逐镜引用。

引用写作 `文档id#锚点id`。原著事实与人物判断分别归因，辨明不知道、忘记、误以为、推测和确知。认知、伤势和持有物按剧情查证。

口播改用易懂说法时，锚点保留原词，按 `mustKeep` 核条件、因果、时序和后文指代。第 28 节用「魔力过载」说明「魔力醉」，环境魔力浓度超出身体耐受，异样在藏戒被踩碎一段时间后出现。分别登记触发和后果，并核回闪里的信息是否为当事人当时所见。 [第 28 节复盘](../../../../docs/productions/chapter070/section28/retrospective.md#分镜返修)

地图标本段可证的地点、方位和用途。只用于比较大小的地名留在解说里，补画的位置和地貌按演出记录。出现标注时接相应台词。

前节采用图缺失时，先查采用指针、前文和制作记录，再按能核实的座次、地标与主光重建。记录依据与新定细节，保存本节采用的共用图。

## 共享素材与逐镜状态

跨节续场按前文核事件顺序。并排看上节采用尾帧、本节首帧和动作完成帧，沿抓点、支点查承重转移，并核地标、站位和主光。尾帧或用户参考图记入 `decisionReference`。多人对话用俯视图标门窗、邻座和走位，先核正反打各一张。第 14 节以木屋的敞门、日光和火塘定位。

在 `visualDesign` 或同等字段记录角色、场景、道具和标志的采用版本、用途与镜号。按当期设定核近景母图的脸、发型和衣装，再核侧身、背影和远景。介绍尚未到场的角色时，定妆插画可表现一项有依据的能力。缩略图核动作或特效能否传达能力，标出切入和切回现场的接点。道具按参考核形制和比例。跨环境缺图时登记缺项，沿采用指针找图，文字暂排的镜头补图后再验。

逐镜用 `knowledge` 引用状态，用 `visualRequirements` 和 `decisionReference` 记录视觉变化。状态转变引用剧情或用户依据。

### 新设定入库

1. 策划和出图时查[设定集](../../../../data/source-webp/chapter07/settings/README.md)。场景、人物、兵器、载具等缺少适用设定时，在本节任务摘要记名称、原著依据、涉及镜号及候选参考图。已有条目的新服装、造型或道具状态，按适用剧情补到原条目。
2. 本节采用后，整理可复用的图和文字。场景按需收空景、平面或反打，人物收能辨认外观及服装的图，兵器收能核形制、比例与握法的图。说明固定特征、适用范围、原著依据和项目美术补充。沿设定集分类保存，更新相应索引和资产清单，登记采用来源、版本、路径及图像尺寸和哈希。候选图和单镜临时状态留在本节记录。 [会议室入库范例](../../../../docs/settings/chapter070/gurall-council-room.md)
3. 收尾前实开参考图和相对链接，检查图片、说明和索引可由 Git 跟踪。遇到忽略规则时只放行对应的设定目录，制作缓存、私有素材和回执留在本节目录。交接时为用户列好本次 `git add --` 的具体路径、核对暂存区的命令和建议提交说明，便于单独提交设定。用户已授权代办时，按授权范围执行。

## 每镜五项信息

在 `shots[]` 内增加 `sourceReview`，保留台词和画面字段。

| 字段 | 内容 |
| --- | --- |
| `sourceRefs` | 支持本镜的原文锚点，涉及前文时补相应锚点。 |
| `mustKeep` | 必须保留的事件、因果和对白含义，非逐字对白用转述。 |
| `knowledge` | 引用本镜适用的 `states` ID。无人物镜可留空。 |
| `visualRequirements` | `{description, basis, sourceRefs?, decisionReference?}`。依据分为 `explicit`（原文明写）、`staging`（具象化演出）、`user-direction`（用户要求）、`continuity`（采用图连续性）。 |
| `forbiddenAdditions` | 本镜不得新增或提前的心理、结果、人物和道具。无额外限制可留空。 |

`explicit` 引用可查原文。其余要求通过 `decisionReference` 指向反馈、设定图、采用图或演出记录。具象化仍须与原著事实相容，保留既有情节。

`eventIds` 列本镜承载的事件 ID，与 `events` 的 `shotIds` 双向对应。

校对前标 `status: pending`。人工核对后标 `reviewed`，将 `narration` 与 `frameDescription` 的 UTF-8 字符串 SHA-256 分别存为 `checkedNarrationSha256`、`checkedFrameDescriptionSha256`。文稿变化时复查更新。生成后的原图另验，用户批准另记。

## 两次检查，各有范围

1. **生成前**核原著关键事件是否覆盖，以及每项陈述和因果是否有依据。查知情边界、身体状态、引语、转述和演出，确定后登记校对状态与文本哈希，再跑结构检查。
2. **生成后**实际看图，核动作、空间、表情、人体和道具。只修绘制错误时核改动及邻镜。台词含义、剧情或画面方案实质变化时重查受影响镜及邻镜的原著依据，跨场景或全节顺序变化时扩大范围。

原著有变时先核差异及受影响的锚点、状态和镜头，再更新版本与证据。用户确认仍绑定实际图文。

## 结构检查工具

从仓库根目录执行下列命令。

```bash
npx tsx .agents/skills/re0-arc7-comic-video/scripts/check-storyboard-sources.ts data/productions/chapter070/sectionNN/storyboard.json
```

源文件相对当前仓库目录，或用 `--root ROOT` 指定。新制作在图像生成前保存 `sourceMapping`、`sourceReview` 并运行检查。旧格式会报缺项，已批准的旧稿继续沿用原记录。

工具核原文哈希、锚点和行号、事件与镜头的双向引用、状态、五项字段及 `reviewed` 的文稿哈希绑定。事件覆盖、语义、知情边界和画面由人工核对。结构报告与分镜 JSON 一起用作分镜阶段输入，原始依据留在本地。
