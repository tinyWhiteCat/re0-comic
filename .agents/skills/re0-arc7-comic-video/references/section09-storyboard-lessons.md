# 第九节分镜与视频制作复盘

整理日期：2026-11-15。范围为第9节《帝国的作风》从分镜返修、正式制作到视频v2交付。以下记录实际遇到的问题、采用的处理办法，以及仍需补足的检查。

2026-11-12完成的分镜v3是历史返修版本。用户随后反馈09身体过长、23红眼、30刀轴、32圆笼及中刀后缺少血迹，继续修订为分镜v4。2026-11-13，用户以“生成视频吧”确认该版本，随后制作视频v1；收到国旗和巨蛇声画反馈后，完成视频v2并交付。分镜批准、代理自查与成片最终确认各有范围，不能互相替代；截至整理时，没有用户对视频v2的最终验收记录。

当前素材、版本、批准范围与证据从本地 `data/productions/chapter070/section09/manifest.json`、`current-storyboard.json`、`current-video.json` 和 `production-state.json` 定位。不得沿用旧文档的“尚未制作”状态，也不得在缺少文件时补造验证结果。本文件不保存临时分享链接或解密片段。

## 小刀与伤口

- 固定[P01道具图](../../../../data/source-webp/chapter07/settings/props/sheets/01-sword-wolf-dagger.png)，统一短直刃、棕皮缠柄、短黄铜护手和扁圆柄尾。尺寸是项目绘图比例，不是原著明确数值；完整规则见[道具说明](../../../../data/source-webp/chapter07/settings/props/01-sword-wolf-dagger.md)。
- 左右按角色身体判断，先沿头、胸背、肩、肘确定朝向。画面左、近镜或侧卧时朝上的肩膀，不一定是身体右肩。
- 同一侧不等于同一入点。用肩峰、衣缝和橙色条纹定位，避免伤口从肩圆头漂到锁骨内侧、上臂或后颈。角色转身、躺下、跌落后伤口仍固定在身体上。
- 刀是固定在身体上的刚性物。肩面或背面旋转时，刀轴投影、握柄缩短和柄尾端面一并变化，不能每镜沿用相同的屏幕斜线。
- 刀轴进入身体体积，护手与小布裂口接触，衣料遮挡合理；不能漂浮、平贴衣服、任意伸长或无依据地贯穿身体。
- 分清时间线：营地内为右肩前外侧中刀；出营后为右肩应急包扎；逃跑时才增加后背肩胛附近的新刀伤。同一把刀不在被刺者身上与他人腰间重复出现。
- 原文没有说明背伤左右，图稿可选定一侧保持，口播不补写左右。背部不入画时，不为展示刀柄捏造拔刀过程或另一处伤口。

## 包扎、人物与空间

- 包扎先固定参考，保持覆盖范围、叠绕方式与旧血渍。第9节本轮以第14镜肩帽式窄叠绕为基准，不能变成方布片、白袖套、大结或披肩。第18镜要求包扎可辨，需调整身体或机位，不用完全遮挡结案。
- 情绪对应当前动作和认知。刚下刀时托德收起友好笑容、保持冷静警觉，与后来恢复社交笑容分开判断。
- 屈膝、侧卧、半坐都追踪头颈、胸廓、腰、髋、膝和双脚，保持同一少年体型；不能靠鼓胀肩背给刀让位。
- 铁笼栏杆接上下横梁、门框闭合；雷姆刘海遮自身右眼，换角度不能露出整张脸，行动能力按当前阶段核对。
- 巨蛇的体量通过人物/树木尺度、前后遮挡、阴影与动作建立，红眼应清楚。第24镜用户指定保留构图，不能改人物站位与尾扫方向。
- 追逐先建立空间间距。第26镜将昴置于前景、托德置于林路远后景，只画唯一斧头嵌树的结果；原文没明确的近身挥砍或投掷动作不补成事实。

## 分镜v4补修：刀伤需要有连续状态

此前把检查重点放在刀的位置和外形，伤口与衣料反应仍不充分，产生“插了玩具刀”的观感。v4把刀口、衣料破损和血迹一起核对，不能只改刀柄。

| 镜号 | 应保持的状态 |
| --- | --- |
| 01—04 | 尚未发生右肩刀伤，不提前添加该伤口或血迹。 |
| 05—13 | 同一右肩前外侧入点，刀柄随身体转向；刀口周围有连续的布面血迹，衣料与护手接触合理。 |
| 14—27 | 右肩应急包扎，覆盖范围、叠绕和旧血渍延续；不能提前出现后背新刀伤。 |
| 28—30 | 才增加肩胛附近的后背新伤，刀轴随背面转向，布面血迹连续。 |
| 31—32 | 31不见肩背时不强行展示刀；32保留右肩旧血包扎，伤势仍在，不能画成已经恢复。 |

本轮另修09的躯干比例、23的红眼、30的刀轴与32的圆形木笼。v4共改14镜，复查全部32镜，未改口播和镜头顺序；这是该轮镜数，不与v3的20镜相加计算独立返修镜数。证据为本地 `/workspace/work/section09-v4/全分镜审查.json`。

## 视频v2返修：国旗、巨蛇与局部误改

### 国旗设定已有，初版仍未落实

项目已有国旗参考，但视频v1仍出现酒红底金色鸟纹旗，初版审查也未拦住这一问题。这是设定应用和检查覆盖的遗漏，不能归结为生成模型随机变化。

处理时实际查看[正面设定图](../../../../data/source-webp/chapter07/settings/flags/sheets/vollachia-imperial-flag-v1.webp)与[已采用场景图](../../../../data/source-webp/chapter07/settings/flags/references/chapter070-section06-shot13.webp)，按[国旗说明](../../../../docs/settings/chapter070/imperial-flag.md)修正21个有旗帜的分镜，包括营地大旗、远景旗、瞭望塔小旗和行军队列旗。统一蓝底、剑贯黑狼、金色月桂、双绣边、卷草角和短流苏，并随景深、折叠及遮挡简化细节。

检查必须区分旗帜与衣物：红披风、围巾和贾马尔的腰布保持角色设定；原著中的红旗医帐也不能批量改成蓝色帝国旗。金色装饰是项目美术设计，口播不把它说成原著明确记载。

### 巨蛇的压迫感要同时落在画面和声音上

23—25镜统一增强红色虹膜、局部光晕和邻近鳞片反光，保持黑色竖瞳、绿色鳞片与唯一白角；24镜沿用用户要求保留的构图、人物站位和尾扫方向。没有添加光束、喷火或新的攻击行为。

吐信声采用有许可的短嘶声与湿润拟音，在巨蛇露面、红眼句末和张口画面的三个时点安排，共5个叠加事件；时点来自最终时间线和实测字词边界。保留声源及许可页面，混入声音后再从最终AAC回读，确认音效实际进入成片且位置对应，不能只检查音效清单。声音证据为 `video-v2/audio-qa/snake-final-aac.json`；这项回读不代表实际听审。

### “只改旗帜”的指令仍可能带来误改

17镜原图没有可见国旗，生成候选却新增了旗帜与胸徽，因此弃用候选、恢复原图。22镜候选误给贾马尔增加胸徽，另作局部修复，恢复原有皮甲。两例说明，局部修改后仍须拿原图对照人物、装备和背景，不能因为目标旗帜正确就整张采用。

本轮实际采用24张改图：21张旗帜修订、23—25三张红光修订。未变图保留原始文件，退回的候选单独记录，不计入采用数量。证据为 `video-v2/visuals-review.json`、`generated-assets.json`、`discarded-generation.json`。

## 配音、字幕、运镜与合成

| 问题 | 处理方法与后续检查 |
| --- | --- |
| 开场品牌读法不稳定 | 首个“Re zero”候选的独立识别结果明显不符，未采用；增加一次片头合成，用“R E 零”的输入表达直接读RE0。显示稿仍保留“Re:0 帝国篇原著解说。”，语音输入的读音别名不进入字幕。源音和最终AAC分别核对，正文配音不跟着重录。 |
| 正确静帧在推进后仍会裁掉关键物 | 13、23、25、32镜收小推进或调整焦点，保留刀柄、白角和圆笼边缘；检查实际视频的首、中、末帧。片尾承接32镜的最终机位，避免重新回到全景。 |
| 逐段拼接可能累计音画偏差 | 单张图生成的视频片段，容器时长可能比真实帧长少一帧，累积曾产生约1.375秒偏差。拼接清单逐段显式填写 `duration = frames / 24`，再检查最终总帧数、帧率和音画时长。 |
| FFmpeg参数与抽帧表达式报错 | 淡出时长使用完整小数 `0.75`；大量抽帧条件改为平衡表达式，避免长串条件超过解析深度。这些修复属于合成实现，不改变画面叙事。 |
| 加了音效不等于最终文件里有正确的声音 | 旁白、音乐、环境声、动作声分别保留；旁白沿用冰糖默认音色与语速，只做固定增益，不加EQ、压缩、变调或时间拉伸。最终编码后再测响度与真峰，并回读新增音效时段。 |
| 返修时容易误用旧缓存或全片重做 | 缓存绑定源图、机位、帧数、字幕及叠加。17镜自身图未改，但前镜16的图改变，转场仍须重做；26—32与片尾共8个未变片段沿用，另26个片段重新渲染。不能仅按镜号判断缓存可复用。 |

片头存在读音别名不代表正文可任意改成同音字；别名只用于已定位的词组，显示稿和已批准语义保持。字幕沿用实际配音对齐和已检查的双语版式，未改内容不重新估算时间。

最终视频为1920×1080、24fps、10977帧、457.375秒。视频v2完成一次全文件解码，实际查看32镜首中末及片头、最长中英字幕、片尾接点，共103张最终抽帧。最终AAC测得约−18.02 LUFS、−2.96 dBTP。证据为 `video-v2/qa/final-technical-review.json` 与 `video-v2/review-review.json`。

## 上传与交付

浏览器访问曾遇到证书信任错误。上传工具采用本会话的临时本地证书固定公钥，并由继承代理及CA的Node连接校验上游HTTPS/WSS；没有关闭上游证书验证。大文件通过流式传输，沿用已验证的显式 `Content-Length` 处理，避免二进制上传使用chunked请求时的兼容问题。这一上传方法由本期 `video-v2/wormhole.ts` 实现，临时证书和凭据不进入公共文档。

交付继续使用Wormhole：官网显示云上传完成后关闭发送页，再用新匿名上下文实际下载、解密整文件，比对字节数和SHA-256。视频与素材ZIP各自核验；素材ZIP实际29项，不包含视频。不能把链接已创建、上传进度完成或拿到密文当作下载验证通过。

到期时间与下载上限按当次页面记录；没有实时剩余次数就不推算。临时链接到期后，应从当前采用文件重新上传、重新核验，无需重生成视频。只有所有必要文件下载验证完成，才更新当前视频及视觉素材指针，保留旧版记录。

## 后续制作需要改进的地方

1. **生成前落实设定。** 角色、匕首、旗帜和伤势状态列入本节实际引用清单，先看参考图，再生成；已有文档不等于已经应用。
2. **按连续镜头检查。** 右肩伤、后背新伤、包扎、血迹、身体转向和人物距离都与前后镜对照，不能只看单图是否好看。国旗和其他背景设定也要进入检查范围。
3. **局部修改后检查非目标区域。** 新增胸徽、旗帜、身体变化和遮挡变化都要与原图比较；不合格候选不采用。
4. **检查最终产物。** 原图通过后仍看实际运镜、字幕遮挡与片尾接点；声音进入最终编码后再回读；交付后再做匿名整文件校验。检查记录绑定实际采用文件的哈希。
5. **补足听审边界。** 本期完成了独立ASR、源文件核对、响度测量和音效回读，没有实际听审。后续有条件时应试听片头、专名、关键音效与人声混合片段；在此之前继续如实记录 `actualListening: false`，不将识别或数值检查写成人工听感通过。

以上改进针对这次暴露的遗漏。分镜v4获批不等于用户已经验收视频v2，局部反馈修复也不替代后续成片反馈。
