# Re:0 第七章漫画解说视频

把仓库中的原著与角色设定制作成连续的彩色关键分镜，再配以解说、运镜和声音。沿用用户在第一节《洗礼》制作中确认的偏好。用户本轮要求优先；第一节的镜头数量、台词、时长和下载链接不作为后续各节的默认值。

完整制作一集时，必须交付视频、两张封面图和视频简介。两张封面默认分别为 4:3（1280×960）与 16:9（1280×720），同一套已确认文案分别排版；同一张图的 PNG、JPG 导出不能算两张封面。只修改某张图、某句配音或单独写简介时，仍按本次指定范围执行。

必须先完成分镜稿并交给用户审阅，得到明确确认后才进入视频制作。分镜稿包含按顺序编号的彩色分镜图、逐镜解说台词、转场说明及预计时长。仅收到“制作某一节视频”的初始请求，不等于用户已确认尚未生成的分镜稿。

## 开始任务

1. 读取仓库 `AGENTS.md` 和 [Humanizer-zh](../humanizer-zh/SKILL.md)。所有新写或修改的自然语言先润色，再核对事实、人物称呼和剧情因果。保留原著文件、逐字引文、代码及时间码。
2. 确认本次是制作新节、修改图文、生成成片、修补音频、制作封面还是重新交付。只执行本次授权的范围；已经确认的画面、声线和台词作为基线。
3. 阅读目标节原文、角色设定和最新制作记录。先看当前 manifest 的版本指向，再读旧版说明；文件名中的 `v5` 不代表该目录里的每份文档都是最新方案。
4. 从仓库和上下文能确定的信息直接使用。章节未指定且无法推断时，只询问章节或范围，并继续检查已有素材。需要新增镜头动效或 Remotion 实现时阅读 [video-shotcraft](../video-shotcraft/SKILL.md)，按本片风格选用配方。
5. 用 [单节任务模板](templates/episode-brief.md)记录来源、目标、素材版本和待办。这是人工制作记录，不是现有脚本接受的配置格式。

遇到读音、停顿、图文偏差或交付返工时，先查[第二节制作复盘](references/section02-lessons.md)。其中记录了问题、实际解决方法和复用边界；具体镜号、帧差和音频测量只用于本节复现。

## 制作顺序

### 1. 读原著，整理事件与解说

通读目标节，再核对必要的前文。为每个事件记录原文位置、人物知道什么、观众需要知道什么、下一步为什么发生。涉及推测、失忆、失去意识或生死未明时，保留原著的确定程度。

解说要把画面难以独立说明的因果讲清楚。例如，第一节拉姆触额头是在通过姐妹共感感知雷姆，不能只说“她扶着头”。类似说明必须有原文依据，不能用虚构内心戏填补。

一镜承载一个主要叙事动作。跨场景用“与此同时”等有实际时间含义的连接；起身、背起、倒地、人物离开等状态变化，要有关键画面或清楚口播。原文有意省略的过程仍可省略。

完成逐镜稿和纯口播稿，先按 Humanizer-zh 润色，再做原著复核。避免只有短句堆叠，也不要为煽情添加后续剧透、确认未发生的死亡，或过度渲染次要摔倒动作。正文译名与原著保持一致；同一人物的展示名和配音读法分别登记。

### 2. 制作彩色关键分镜

每镜计划写明：原文依据、场景、人物位置与朝向、视线、表情、主要动作、手脚归属、服装连接、构图焦点、前后镜衔接、配套解说。镜头数量由剧情决定，不固定为 24 镜。

生成前实际查看角色设定和相邻已确认图。使用当前可用的图像生成或编辑工具；图像编辑必须引用待改图及必要参考，不能只凭记忆描述。工具不可用时说明缺少的能力，先完成可做的文稿与分镜计划。

画面要给字幕与后续推进留下空间。画好后逐张查看，并连看前后镜；拥抱、背负、勒颈、摔倒、握箭等复杂动作，逐条追踪头—颈—肩—上臂—肘—腕—手的连接，清点脚与鞋。不能用“可能被挡住”接受明显断裂。

单镜返修保留编号，记录候选与最终采用版本；修改图、解说及素材清单中受影响的项目。具体检查见 [图文与成片验收](references/quality-checklist.md)。

### 3. 交付分镜稿，等待用户确认

完成图文自查后，交付实际可查看的分镜图与逐镜稿，标明版本、镜号、台词、转场、预计停留时间和拟定运镜。可用图册或预览页总览，并提供原图及文稿入口；不能只发本地路径或一句“分镜已做好”就请用户批准。

将任务标为“分镜待确认”，说明这是用户要求的制作前审稿步骤，请用户确认这一版或指出修改处。未收到明确确认前，不开始本期正式配音、混音或视频渲染，也不以沉默、等待时间或 Agent 自查通过代替用户确认。可以继续整理素材和检查环境。若仅请求生成分镜稿，到此交付即可。

记录确认的版本、图稿/文稿路径与哈希、用户确认原话或消息引用、时间和批准范围。用户针对已展示的当前稿回复“确认”“按这版生成视频”等，可作为进入视频制作的依据；已有同版本确认时直接沿用，不重复询问。

用户要求修改时，先修订并提交受影响内容复核；剧情、镜头顺序、主要画面或台词含义发生实质变化，需要确认更新后的内容再制作视频。已确认稿的小范围读音或编码修复，按用户指令执行，不重复审核整套分镜。分镜确认与封面文案审核分别记录，不能互相替代。

### 4. 配音、读音与双语字幕

核对当前分镜稿已有用户确认，再用已确认声线生成有代表性的短样：普通叙述、情绪对白、专名、片头多音字。检查通过后生成其余内容。用户已确认的样音或参数可以复用，不为每个小修复重新索取确认。

遇到新的简称或外语读法、连续返修的连读或停顿问题时，先用覆盖问题词和必要上下文的几秒纯人声核验。用户要求先试听，或读法、节奏仍需用户选择时，交付短样并在确认后应用到整片；其他情况按已有授权执行，不新增重复审批。保留未改参数，一句连续合成；确认记录绑定实际录音及哈希，已批准的同一录音直接复用。读法正确、停顿自然和用户满意分别核对，ASR转写与静音测量不能替代试听。具体案例与短样流程见[第二节复盘](references/section02-lessons.md#re0读音正确还要连贯)。

普通段落按一镜或完整语义组连续合成，不按每条字幕切碎。各组显式使用 `mimo-v2.5-tts`、`voice: 冰糖`，顶层与组内均不提供 `style`，正文不加括号语气或速度标签，不传克隆参考音频。保持服务默认音高和语速，按已确认的自然说话方式解说，不再为每镜追加声音设计或情绪指令。对照已选样音检查音色、连续性与专名读音，服务失败时明确报告，不自动换声线。

保留[A 的设计描述及样音](../../../docs/voice-profiles/mimo-clear-soft-a.md)供旧版复现，不能把此前的 A 样音确认改写为已确认克隆结果。历史 Edge 服务的原生语速、音高、音量规则也只用于旧版复现。新制作不声称复刻了蕾姆声优；通用 MiMo CLI 省略音色时仍为茉莉，必须显式选择冰糖。

持续沙沙声或电流声应先定位到原始 TTS、背景音、增益、拼接或编码环节，再修复来源；不能默认加降噪掩盖问题。响度或静音测量不能证明声音自然，没有实际试听就如实标明。

专名连续输入，不在姓名内部加空格、标点或切分语音组。“艾米莉娅”检查是否连读；“原著解说”的“著”读 **zhù**。优先调整上下文；必要时使用有记录的词组级 `pronunciationOverrides`，只影响 TTS 输入，字幕和显示稿仍为原文。第一节的 `原著 → 原住` 是已验证的特定读音修复，不能把所有“著”全局替换。

用户于 2026-11-02 补充要求 RE0 连着读，指出上一版 `R，E，零` 的停顿过长。读法仍是英文字母 R、E 加数字“零”，三个音自然连读，取消在三个音之间强制加逗号的 TTS 输入规则。用户随后试听并确认了输入 `R E零，帝国篇原住解说，第七章第二节。` 对应的 4.32 秒样音；字幕和标题仍显示 `Re:0` 和“原著”。保留简短片头，不恢复完整中文书名。

本轮已先交付短音频，用户确认“没问题了，以这种方式重新生成视频吧”。本次视频直接复用 `intro-connected-audition` 的已确认源录音，不重合成片头，以免读法漂移；文件、输入和哈希见[冰糖样音记录](../../../docs/voice-profiles/mimo-bingtang-default.md)。以后相同片头可在核对文本、版本和音频哈希后复用。节号或其他文字变化时，按当前冰糖音色规则生成并检查新录音，不能套用旧音频，也不能把本次确认扩展为所有新录音已确认。原技术记录中的 ASR 结果及代理未实际听音的事实保留，用户后续试听确认另行记录。

“Cor Leonis”按用户偏好口播“狮子心”，首次出现时在字幕中注明 `狮子心（Cor Leonis，拉丁语）`。注释只显示，不交给 TTS；字幕对齐使用实际口播文本，不为未朗读的拉丁文字分配时间。

中文显示稿、口播和英文翻译来自同一冻结版本。英文保持同条意思、归因和不确定性，不擅自补剧情。按实际合成音频边界对齐字幕；MiMo 不返回逐词时间，需要另行语音对齐。改了词或语速就重算受影响时序，不沿用旧时间码凑时长。

### 5. 运镜、混音与片头片尾

每镜记录归一化焦点与起止倍率。第一节的缓慢推进约为 `1 → 1.08–1.16`，仅作起点参考；根据人物和动作调整，不统一居中放大。抽看起、中、末帧，确保双手、脚、武器及表情仍可理解，字幕在运镜之后叠加。

背景音随场景情绪铺陈，动作音效对应实际发生时刻。用户特别要求木棒击中、切断树枝等动作的声音；逐镜核对实际事件后安排，避免为静止画面添加无依据的动作声。音乐与音效应能听见，也要让解说清楚，不能仅因音轨存在就认为声音层次足够。登记音频来源和许可条件；人声活动窗口中，第一节人声平均比音乐高约 21 dB，可作起始参考，仍须检查成片听感。

片头保持简短，片尾沿用最后一镜的最终构图与亮度，再淡入字标和淡出全片，避免黑闪或跳回全景。早期 JOJO 箭头和正式宋体片尾已被后续 Re:0 风格替代，不作为默认模板。

新节先按技术参考核对脚本输入和输出，再执行。已有脚本含第一节硬编码，不能仅改一个输出路径就宣称支持任意章节。新增应用逻辑或脚本用 TypeScript；若改前端，继续用 React 和 Ant Design。

### 6. 验收、封面与交付

按 [验收清单](references/quality-checklist.md)检查原著、每张图、声音、字幕、运镜、片头片尾与完整成片。出现问题时修复对应环节，保留已确认版本；新音频导致时长变化时，重新对齐后续镜头、字幕、音乐和音效。

局部改音频时，先核对正文文字、源音和相对时间不变，再按新旧片段的实际帧差平移后续内容，并验证未改区间PCM和缓存来源。验收重点覆盖修改处、接缝及受影响字幕，最后检查完整成片；具体步骤见[小范围修复](references/production-pipeline.md#小范围修复与验证)。制作、上传和邮件发送的状态分别记录，实际交付成功后再更新当前版本指针。

封面先整理短标题供用户 review；已经批准的文案直接使用，不重复询问。主标题用真实的情感落差，系列名与节名保持清楚。完整制作需生成 4:3 与 16:9 两张封面；每个比例分别构图，不压扁人物或裁掉文字。只改标题时保留其余内容。图像生成后逐张核对文案与实际尺寸。

第二节封面的重心是昴与失忆后的蕾姆之间的情感对立，可用分隔肖像表达，不暗示本节已重逢。蒙面人作为次要角色出现时，按已确认分镜核对短剑的长度和握持，不能画成赠给昴的短刀。

视频简介写出本期冲突和讲述范围，保持自然，不编后续结局，保存为 `description.txt`。完整制作的核心交付为成片、4:3 封面、16:9 封面和视频简介，逐项验收；字幕、口播及素材说明一并归档。按 [交付与发布参考](references/delivery-and-publishing.md)上传、匿名下载并核对文件哈希，保存交付记录。缺少任一核心产物时，不报告整期制作已完成。

素材 ZIP 只收录封面、简介、字幕、口播稿和说明清单等非视频资料。1080p、720p、无配乐版、预览片等所有视频均单独提供下载；打包后核对实际文件清单，确保素材包内没有视频。

2026-11-02，用户确认 Wormhole 交付可用，后续视频默认上传地址为 https://wormhole.app/，无需每次重新确认平台。此要求取代此前文叔叔默认上传和双邮件安排：视频链接直接发在聊天里，完整保留 `#` 后的解密片段；只寄素材邮件。先核对当前会话授权的收件人和已有回执，已有相同素材的 API 接受记录时不因更换视频平台而重发。每次上传均须等文件完整传输，再匿名下载核验哈希，记录当次有效期和下载次数；保留期及预览能力以实际页面和检查结果为准。

最终说明实际完成的内容、链接与有效期。局部路径不等于用户可访问的下载链接；上传网盘不等于发布到 B站或 YouTube。链接过期时优先重新上传本地成片，不重做视频。
